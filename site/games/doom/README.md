# STOINLY COMPUTER

A copy of Doom (1993) built from the 33 SERIES 1 trading cards and the running gags of [stoinly.computer](https://stoinly.computer/). Six maps, one per hour of a night in 1995, from the White Hen at 9 PM to the Rehab parking lot at dawn. The vehicles of a suburban adolescence hunt you, the strong women are stronger than you and that is OK, the special guests are cordially invited, and the three ??? cards are waiting at the end.

The renderer, the textures, the fonts, the props, the weapons, the sound effects and the music are generated by the code in this folder. The enemies are the site's own trading cards, photos and all (the owner's decision of 2026-11-03): `tools/photos.py` bakes each card into the sprite sheets, and every photo is credited, as the site prints it, on the credits crawl (main menu, CREDITS).

The site's style runs through the whole game: the rainbow wordmark, the starfield, the lime ticker, rainbow rules and outset navy buttons. Kills shred cards into confetti with hit flash, hit-stop, pop-up numbers, combo and streak callouts and synthesized stings. Each map has three stars (finish, kills 75%, par or all secrets), stars and FOIL unlock weapon skins and HUD themes in THE LOCKER, and there is a daily challenge, a day streak and a daily chest. Nothing costs real money. The hooks save under `stoinly.doom.meta.v1` in localStorage.

## STOINLY NEXUS settings

The game reads the shared STOINLY NEXUS settings (`src/web/stoinly-settings.js`, a byte-identical copy of `stoinly-nexus/shared/stoinly-settings.js`; recopy it and compare with `sha256sum` when the nexus changes it). With no saved settings it plays exactly as before. Only `src/web/main.js` reads them; the game gets plain values (`app.configure`, `app.setBindings`), and changes made in another tab apply at once.

- **Audio:** sound effects times the nexus sfx volume, music times the nexus music volume (mute included), on top of the in-game sliders.
- **Motion:** shake and particle counts scale; with flashes off there is no white hit flash, no gold pickup flash, no blinking text or badges, no twinkling stars, and flickering or strobing lights hold still; a power-up running out stops blinking. Reduced motion (the OS setting or the nexus one) also stops sliding rainbows, wobble and hit-stop. `&reduced=1` still forces it for tests.
- **Display:** the colour-blind filter goes on the canvas. Performance mode halves the particles and draws the 3D view at half horizontal resolution, as Doom's low detail did. Text scale is partial: it enlarges the pop-up numbers and the announcer callouts and the DOM text (the NEXUS link, the error strip); the bitmap fonts of the menus, the HUD and the messages stay their size. Fullscreen is asked for on the first key or click.
- **Controls:** every key goes through `keysFor('doom', action, defaults)`; the actions and their default keys are in `src/game/controls.js` and `stoinly-game.json`. Keys are physical keys (`KeyboardEvent.code`), so on a non-QWERTY layout the defaults sit where W, A, S and D are on a QWERTY keyboard. The mouse is not rebindable, and the letters typed into a save name are whatever the keyboard types.
- **Back to the nexus:** opened with `?from=nexus`, the title, every menu and the pause screen show a ◄ NEXUS link to `/`, and the main menu gets a ◄ NEXUS item.

`stoinly-game.json` is the manifest the nexus reads. `tests/web/live-settings.html` (open it from a server) checks that settings written by another page reach the game live.

## Playing

Open `index.html` in a browser (it works straight from the file; Firefox is what it was tested in). Or serve the folder and open it:

```
npm start            # python3 -m http.server 8000 --bind 127.0.0.1, then open http://127.0.0.1:8000
```

| Key | Does |
|---|---|
| W, S or Up, Down | walk forward, back |
| A, D | step sideways |
| Left, Right | turn (Alt + Left, Right to step sideways) |
| Mouse | turn (click the screen to capture the pointer) |
| Ctrl or left mouse | fire |
| Space or E | use: doors, switches |
| 1 to 7, wheel | weapons (1 switches between your hands and THE RAZOR) |
| Shift | walk (with ALWAYS RUN on, the default) |
| Tab | the map |
| P | pause |
| Esc | menu: new game, options, load, save, YOUR COLLECTION |
| F2 or F5, F3 or F6 | save, load |

## Layout

```
index.html            the game
src/core/             renderer, map compiler, palette, assets, synth, music (no DOM)
src/game/             things and AI, the level's machinery, the player, HUD, screens, the app
src/web/              the browser shell: loop, input, audio
levels/               the six maps (ASCII grids) and the kit that reads them
tools/                generators for every asset: textures, models, fonts, HUD art; the packer
assets/build/         sheets.js, all pixel data, generated by `npm run assets`
docs/                 design.md (what the game is), architecture.md (how it is built)
tests/                unit tests, the level checker, the soak test, render and play harnesses
```

## Checking it

```
npm test             # unit tests, every level finishable, every level survives play at three skills
npm run levels       # the reachability report per map, with monster counts per skill
npm run soak         # 3000 tics per level per skill with an invulnerable player firing at everything
npm run smoke        # renders a showcase level to assets/png/smoke/
npm run assets       # regenerates every texture, sprite, font and HUD image, then packs them
```

Headless screenshots of any moment: open `index.html?test=LEVEL,TICS,KEY:TICS+KEY:TICS` (for example `?test=0,5,w:30%2BArrowLeft:8`; write `+` as `%2B` in a URL), also `?test=title`, `?test=inter`, `?test=finale`, `?test=collection`, `?test=locker`, `?test=chest` (`&pokes=N`, `&open=1`), `?test=daily`, `?test=credits&scroll=N`, `&menu=main`, `&map=1`, `&at=X,Y,DEG` (put the player there), `&mhp=N` (every monster's health), `&pause=1`, `&date=YYYY-MM-DD`, `&demo=1` (a sample hooks record), `&reduced=1`, `&settings=JSON` (nexus settings for this page only, for example `{"display":{"colorblind":"deuteranopia"}}` URL-encoded; the stored settings are put back once the frame is drawn), `&from=nexus`, and `&bench=1` for frame timing. Test runs use an in-memory store, never the real save. Script keys may be old key names (`w`, `Control`) or `KeyboardEvent.code` values.
